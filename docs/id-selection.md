# ID 选型指南

选择生成器时，先回答四个问题：

1. 唯一性范围是单 JVM、单库还是全局？
2. 是否需要按生成时间排序？
3. 是否必须是纯数字/固定长度/跨语言可读？
4. ID 是否会被外部用户看到，能否接受可枚举或时间泄露？

## 对比

| 生成器 | 输出 | 时间有序 | 唯一性 | 可枚举 | 安全随机 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| UUIDv7 | 36 字符 UUID | ✅ 毫秒 | 全局 | 否（但时间可推断） | ✅ | 数据库主键、事件 ID、跨系统 |
| UUIDv8 | 36 字符 UUID | 取决于预设 | 全局（应用自定义） | 取决于预设 | ✅ | 需要自定义位布局/厂商扩展 |
| ULID | 26 字符 Crockford Base32 | ✅ 毫秒 | 全局 | 否（但时间可推断） | 可配置 | 字符串主键、日志/事件、索引友好 |
| KSID | 19 位以内数字 | ✅ 毫秒 | 全局（WorkerId 唯一） | ✅ | ❌ | 数字主键、高吞吐、单库/分库 |
| BIZ | 模板决定 | 按日期/序列 | 业务组合内唯一 | 部分 | 可含随机段 | 订单号、业务单号、对账 |

## 决策路径

```text
需要外部标准 UUID？
  ├─ 是 → UUIDv7（时间有序）或由其他库提供的 UUIDv4
  └─ 否
      ├─ 必须是纯数字/高吞吐？
      │    ├─ 是 → KSID（多实例必须分配唯一 WorkerId）
      │    └─ 否
      ├─ 需要人类可读的业务含义？
      │    ├─ 是 → BIZ（模板 + 序列 + 校验位）
      │    └─ 否
      ├─ 需要 26 字符、Crockford、可排序？
      │    ├─ 是 → ULID
      │    └─ 否 → UUIDv7 / UUIDv8
      └─ 需要固定自定义位布局？→ UUIDv8
```

## 场景建议

| 场景 | 建议 | 原因 |
| --- | --- | --- |
| 数据库主键（Postgres/MySQL） | UUIDv7 或 KSID | 时间有序，减少索引碎片 |
| 订单号/业务单号 | BIZ | 可读、带日期、可校验 |
| 事件/日志 ID | UUIDv7 或 ULID | 可按时间排序 |
| 分库分表数字主键 | KSID | 紧凑、数值索引友好 |
| 对外 API 资源 ID | UUIDv7 | 不暴露连续序列 |
| 需要随机不可预测 | UUIDv7/UUIDv8 RANDOM | SecureRandom；不要用 BIZ 序列 |
| 跨语言/跨系统交换 | UUIDv7 | RFC 9562 标准格式 |

## 长度与存储

- UUID：`char(36)` 或数据库 `uuid` 类型；
- ULID：`char(26)`，大小写统一（KnitID 输出大写）；
- KSID：`bigint`（Java `long`，正数）；
- BIZ：按模板计算长度，建议数据库列留余量，模板上限 128 字符。

## 安全注意

- UUIDv7/ULID 的时间前缀会泄露大致生成时间；不要用于需要隐藏时间的场景；
- KSID/BIZ 的序列可枚举，不能作为令牌、邀请码、密码重置码；
- `{random:n}` 使用普通随机源，不是密码学安全随机；
- 可预测 ID 可能导致越权遍历，请在业务层鉴权。

## 性能参考

开发机单线程 JMH（非正式报告）：UUIDv7 ≈ 17.6M、ULID ≈ 6.0M、KSID ≈ 2.8M、UUIDv8 ≈ 2.7M、BIZ ≈ 0.63M ops/s。详见 [基准报告](benchmark-report.md)。

## 迁移已有 ID

见 [迁移指南](migration.md)。ID 格式变更通常需要双写/回放和新旧列并存，不能只替换生成器。
